## 1. Question and stop rule
Does a Gemma-4-E2B-it adapter trained on the clean synthetic tasks beat the untuned model, in the same compact-list stack, on the screening bank FK (F 81 + K2 74 tasks, 155 in total)? Two arms: A (target = JSON call list, thinking off) and B (target = two or three plain sentences of reasoning in the thought channel, then the call list; thinking on). **Both arms are judged against the thinking-ON untuned model.** Stop rule: if neither arm meets the screen, fine-tuning ends; both arms, the base runs and the row counts are reported. FK shares its author with the training data, so only the BFCL 200 (G4, separate go from Sans) can settle a claim; nothing here is a thesis result.

## 2. Base references (running, `sft/g3_base.sh`, attempt `r6g3/attempts/20261110_033718_base.XtrzLh`)

## 4. Training (identical for both arms except the target and the thinking switch)
Adapter as G1: layers 8 to 34, rank 16, scale 2.0, q/o/gate/up/down (+ k/v where they exist, 149 modules), lr 1e-4, 5% warm-up then linear decay, Adam, gradient accumulation 4, prompt mask, seed 61. **2 passes** over all rows. Rows over 6,999 tokens are dropped and counted (the P0.3 memory limit; none are over it in either arm: maximum 6,819 and 6,877 tokens). A checkpoint is saved at the end of pass 1 (`adapters_pass1/`), kept, not scored unless the advisor asks. Validation loss on the valid rows is logged at the end of each pass and is never used to choose anything. Divergence rule as G1 (exit 5). Training cap 30 h (`--max-seconds 108000`); whole chain 34 h.
* Render parity: the prompt the thinking-matched compact-list server builds equals the trainer's for every training row; arm A 0 `<|think|>` markers, arm B exactly 1 per row (`g3_parity.py`, checked on the base server and again on the adapter server).
* **Smoke (12 micro-batches each, 2026-11-10 06:09 and 06:14 ET, not results):** arm A 13.32 s per micro-batch at 3,821 mean tokens (3.49 s per 1,000 tokens), peak 33.21 GiB, GGUF audit error 3.1e-4, identity ok, render parity 2,667 rows with 0 mismatches and 0 think markers; arm B 13.14 s at 3,873 tokens (3.39 s per 1,000), peak 35.53 GiB, GGUF error 3.2e-4, parity 2,494 rows with 0 mismatches and exactly 1 marker per row (2,494). **Estimated training time [ANALYSIS]: arm A 5,334 micro-batches x 13.3 s = 19.7 h, arm B 4,988 x 13.1 s = 18.2 h, plus the validation sweeps; both under the 30 h limit, so two passes are kept.** Full-length rows (maximum 6.8k tokens) reach about 44 GiB.
