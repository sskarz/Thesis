## 3. Comparators and the primary comparison
Arm A is trained and served with thinking OFF. The untuned model scored better with thinking ON on the screening banks (59 and 61 against 54 of 155), and the paper's reported stack uses the default template (thinking on). So an untuned comparison with thinking off alone would flatter the arm.
* **Comparator 1 (primary): untuned model, same stack, thinking ON,** a fresh run on the same server build and day (not the 88 of 200 from Run 84, which was a different day; the paper's own runs of one configuration differed by up to 6 tasks).
* **Comparator 2 (thinking OFF) is not run under this registration** (the agreed order has two untuned runs, both thinking ON). On the screening banks the untuned model with thinking off scored 54 against 59 and 61 with thinking on, so comparator 1 is the harder test. A thinking-off untuned run would need a new go and a dated amendment.
* **Arm (selection rule, inputs stated before arm B's score exists):** the higher run-1 FK composite of arm A and arm B, ties to arm A; the chosen arm must also have passed the repeat gate (section 7, item 3). **Inputs so far: arm A = 118 of 155 in run 1 and 118 in the restarted repeat (F 64, K2 54; `G3_A_REPORT.json`); arm B = pending** (training since 2026-11-11 02:00 ET, then its screen). The combined retrain is **not** scored in this registration; it comes after G4 and is exploratory (item "One model" below). If arm B is chosen it is served with thinking ON and compared with comparator 1 as above; if arm A is chosen it is served with thinking OFF.
* **Decision rule:** the claim "a trained model beats the untuned model" holds only if the arm beats comparator 1 under the criterion in section 5. A win over comparator 2 only is reported as such and is not the claim.

* **Exactly one trained model is scored on the BFCL 200 under this registration,** chosen from FK screening results only (section 7, item 3). Any second model scored later (arm B, the combined retrain) is **exploratory**, labelled so in every report, and outside this registration's decision rule. **No BFCL outcome feeds a choice of model, a retrain, or a change of data.**
* **Comparator validity check (stack verdict), run first.** The fresh untuned thinking-on run is run **before** the arm and its result is compared with Run 84 (88 of 200) and Run 83 (84 of 200). **Settled by Sans (2026-11-11), basis proposed by me:** the stack counts as reconstructed correctly if the fresh score lands **between 82 and 94 (within 6 tasks of 88)**. Basis in the paper: the same full stack scored 77, 71 and 72 (spread 6), and the shorter list scored 84 and 88 in its two runs (spread 4). Outside that band the run script stops after the comparator run, writes the verdict and the score with a timestamp to `STACK_VERDICT.json`, and **does not start the arm**; Sans decides whether to look for a configuration difference (section 2) or to proceed with the result labelled "stack not reproduced". The verdict is written before the arm's score exists, so it cannot depend on the arm.

* **Why two pairs:** the paper's own repeats of one configuration moved 15 to 18 tasks between runs and 6 tasks in total score (77 against 71 and 72). A single pair cannot tell a 3-point difference from noise. The primary plan therefore uses two pairs. The agreed plan is two pairs.

## 5. Test and margin (from the paper's own paired method)
* **Test:** exact two-sided McNemar on per-task pass/fail over the same 200 task ids (paper, "Statistics"), alpha 0.05, uncorrected, as in the paper's shorter-list test; with two pairs, the paper's task-level sign test (each task counted once, ties dropped) as the combined test.
* **Statistic that carries the margin.** *Net* is defined as follows. **One pair:** net = (tasks only the arm solves) minus (tasks only the comparator solves) in the paired table; the test is the exact two-sided McNemar test on those discordant tasks. **Two pairs:** each task is counted once by how many of its two runs each side solved; net = (tasks where the arm solved more of its runs) minus (tasks where the comparator did); the test is the exact two-sided sign test on those tasks, ties dropped (paper glossary entry "Sign test", `paper/main.tex` line 445, and the shorter-list analysis: 33 against 17, p = 0.033). Each pair's own net is also reported, and the direction must agree in both pairs for a "win".
* **Reading of "paired exact test per pair" (my reading, to be confirmed):** each pair's exact McNemar p and net are reported separately, as in the paper's Table of the shorter list; the outcome table below is applied to the combined two-pair sign test (the paper's test "we rely on"), with the pair-direction rule.
* **Margin [REGISTERED 2026-11-11 before any run, by the Thesis bot as a derived proposal; Sans's terms name the test but not a margin; Sans may change it only before the first trained-run score is read]:** 8 tasks of net, in the statistic above (4 points on 200). Reason: identical runs of the paper's stack moved by up to 6 in total score.
* **Outcome table, fixed before any run** (primary comparison only: arm against comparator 1; applies if the stack verdict is "reconstructed"):

| Outcome | Condition | How it is written up |
|---|---|---|
| Win | p < 0.05 and net >= +8, and both pairs (if two) have net > 0 | "the trained model solved more BFCL tasks than the untuned model under this stack", with the counts; the paper's hedges stay (single model, single seed, one teacher) |
| Suggestive | p < 0.05 and 0 < net < +8; or net >= +8 and p >= 0.05; or p < 0.05 and net >= +8 but a pair has net <= 0 (pair-direction rule failed) | "suggestive", not a win; no stronger wording |
| No difference | p >= 0.05 and -8 < net < +8 | "no difference detected"; not evidence of equality |
| Arm worse | p < 0.05 and net <= -8 | reported plainly as a negative result |
| Suggestively worse | p < 0.05 and -8 < net < 0, or p >= 0.05 and net <= -8 | "suggestively worse", not a loss; no stronger wording |

  If the stack verdict is "not reproduced", the same table is applied but every statement is labelled "stack not reproduced" and read as relative to the fresh comparator only. The thinking-off comparator is reported with the same table as a secondary result and decides nothing.
* **Not claimed:** anything about other models, other splits or edge hardware (scope is fixed).
