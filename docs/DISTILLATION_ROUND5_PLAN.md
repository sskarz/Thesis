* **Composite runs.** B_j = 35 + K2 pass count of base run j; N = 81 + |K2|; mu_B = (B_1+B_2)/2; B* = the higher composite base run (ties: B1). ## Stage 5B (on-policy same-state preference pairs)
Selection and diagnostic rules below are frozen before any E2 outcome is known.
**B1 states.** All eligible states after the A0 guard audit (expected ~460; the 600 cap is inactive). Teacher-labelled kept states from r3 old/new + G, deduped by prompt, minus drop tasks and any guard-hit source task.
**B2 sampling.** Per state: greedy + 5 samples at T=0.7, bar GGUF, no adapter (verified via /lora-adapters = []), base harness, think marker, max_tokens as in Round 3 sampling, finish reasons and truncation logged. Incomplete/truncated generations excluded symmetrically. Parsing follows the strict Round 4 JSON-list filter (permissive parse accepted only for logging).
**B3 matching and pairs.** One matcher, fixed now: calls canonicalized by argument-key order, call order preserved. A response is **exact-match** if its canonical calls equal the teacher action. A non-matching response is classed: *verified inferior* (replay returns an execution error, or it is `[]` while the teacher acts and the labeller's stop_early rule would drop that teacher state's stop), *verified equivalent* (labeller same_effect on returns; excluded from pairs), or *unresolved alternative* (excluded from pairs; counted). Pairs: chosen = exact-match response (passing the distill_rationalize acceptance: nonempty reasoning, <= 3500 chars reasoning), rejected = verified-inferior response, same state; <= 2 distinct pairs per state; deterministic order seed 61; identical prompts with conflicting labels dropped; task-disjoint validation split of ~10% of tasks. Both branches <= 6000 tokens total with prompt, no truncation. A chosen response repeated across pairs appears with the same multiplicity in the SFT control. This is **teacher-action preference learning** (the teacher's action replays cleanly: act_ok is an execution/grounding check, not continuation success); claims about better recovery would need a separate continuation audit and are not made here.
**Diagnostics fixed now (reported before and after every filter):** source/API, recovery status, label kind, action/call count, original student-target agreement; rejection reason (execution error, premature stop, missing lookup/action, other); prompt/reasoning/answer/total lengths and chosen-minus-rejected length; sampling index; finish reason; unique tasks/states/chosen responses/pair multiplicity. **Pair floor (applied after all filtering and the validation split):** >= 150 train pairs from >= 50 tasks, else stop B; A results stay. No hinted rescue.
**B4 training (single pre-registered run each, no search).** Policy and reference: bf16 MLX base (reference = adapter disabled), same q-only adapter family and seed as A2, 80 optimizer updates (grad accum 4, 320 pair microbatches), no prompt/branch truncation (overlength pairs rejected, as run_dpo_full_mlx.py), logits cast to FP32 before log-softmax, think marker in prompts. **DPO:** sigmoid DPO, beta 0.1, lr 1e-5. **Chosen-only SFT control:** same chosen responses, microbatches, order, seed, adapter, optimizer, **lr 1e-5** (objective normalization still differs, so no equal-optimization-dose claim). Reference log-probs precomputed with one base copy, serving unloaded. Preflight, all required before training: policy/reference agreement and loss ~ ln 2 at init, causal and assistant-only masks, numerical gradient-direction check, finite gradients, adapter-only gradients, and a memory preflight on the longest pair (a full 6000 x 262144 logits tensor is ~3.15 GB BF16 / ~6.3 GB FP32 per branch on a 48 GB machine; if branch graphs do not fit, compute branches sequentially with the shared DPO coefficient; OOM stops the arm, no silent truncation or window change). Monitor margins, per-segment log-ratios, adapter delta norms; do not tune on FK. The old trainer (git history, Thesis repo commit 34e0d5b) is adapted only after Codex reviews the adapted code (module list, imports, scale, update logic, truncation, dtype changes made explicit).
**B5 evaluation.** DPO on FK per the shared rule. If DPO passes the screen, the chosen-only control is run **twice** (restarted) on FK; attribution to the preference signal is claimed (descriptively) only if both DPO runs exceed the mean of the two control runs; otherwise no attribution. If DPO fails run 1, the control is not run (reported as not run; the preference contribution is then unmeasured).
Mechanism diagnostics (descriptive, not selection): empty-after-error rate (stageA_diag.py), pass by API class, paired gains/losses, preference accuracy by stratum.

## Amendments from Codex r28 (v2 -> v2.1; frozen before any E2 outcome)
1. **K2-inclusive audit.** K2 is not certified until its chain finished with validated inputs and a clean final filter report. After K2 is frozen (path + sha256), re-run the source-history guard audit and the training-row provenance check with K2 included (explicit paths). Training data are frozen only after that; exclusions apply identically to both A2 arms and to B. A2 training does not start before this.
2. **Matcher precedence** (replaces the equality test inside the distill_rationalize acceptance; only its reasoning constraints are kept: nonempty reasoning, reasoning <= 3500 characters). For a sampled response with canonical calls c at state s with teacher action t: (1) exact match: canonical(c) == canonical(t) (argument-key order canonicalized, call order kept) -> chosen candidate; (2) execution error: replaying c at s yields an error by iffc_state.is_error_result -> verified inferior; (3) premature stop: c == [] while t != [] and the labeller's stop_early test, applied to the hypothetical empty action at s, drops it -> verified inferior; (4) return-equivalent: same_effect (equal stringified execution returns; NOT claimed to be state-equivalent) -> excluded; (5) anything else -> unresolved, excluded. Counts of every class are reported.
3. **Eligibility and selection, frozen.** recovery state = after_error(messages) of sft/build_recovery_rows.py; correction state = kept label whose canonical action differs from the student's recorded action; eligible = kept AND (recovery OR correction). States ordered by (task_id, episode_id, step); within a state, chosen candidates and rejected candidates are each ordered by sample index (greedy = 0 first); pairs = first two of zip(chosen, rejected) (fewer if fewer exist). Validation = tasks ordered by sha256(task_id), the first ceil(0.10 x number of tasks that have >= 1 pair) tasks. No other pair selection.
4. **Diagnostics added.** Per-stratum chosen/rejected log-ratio changes and preference accuracy (strata = rejection class, recovery vs correction, API class, label kind); counts of exact / return-equivalent / unresolved with reasons. DPO objective = full-response SEQUENCE SUMS of log-probs over assistant tokens, no length normalization anywhere (reference-adjusted), sigmoid loss.
5. **B5 disposition.** If DPO passes run 1 but fails the repeat: screen not passed, control not run (reported). If the screen passes: control runs twice (counterbalanced order, restarted); report DPO_i - control_i by run index and attribute to the preference signal only if both DPO runs exceed the control mean AND DPO_i > control_i for both i.
6. **Preflights.** Memory preflight = longest-pair forward AND backward pass with gradient checkpointing enabled; A1 adds a conversion/serving memory check (single process; BF16 GGUF ~10 GB plus context; no concurrent MLX job).
7. **Local limits (registered now).** A1 <= 3 h total; each FK bank run <= 2.5 h wall (kill and report, failed attempt preserved); each training run <= 3.5 h; pair sampling <= 4 h; generation max_tokens as in the Round 3 sampler. **Budget reconciliation:** Round 5 spend is reconciled from the API logs after every paid chain; no new paid call unless reconciled spend + the next call's cap <= the $2.5 Round 5 cap; the K2 chain's actual cost is recorded when it ends. The K2 chain script is not fail-fast (it was started before r28): each stage's output is checked by hand before the next result is used, and K2 is certified only after validation.

## Amendments v2.2 (2026-11-08, after A1 and the DPO-trainer preflight; before any E2 or pair outcome)
1. **A1 rerun.** Attempt 1 rendered `<|think|>` twice (content marker plus the server's own); archived, not used. Attempt 2 strips the content marker so exactly one is rendered (asserted per prompt). Attempt 2 results are the A1 record (see runlog). A repeat of q4_base measured run-to-run variation (a fifth condition; not in the original four).
2. **Sequence cap.** The B3 cap "both branches <= 6000 tokens" is replaced by <= 9500 total tokens (the SFT max_seq; the AB rows reach 8,950), because the shared prompts alone average ~6,000 tokens and a 6000 cap would discard most states. Still no truncation: overlength pairs are rejected.
3. **Training time cap.** Measured on the longest 6000-token synthetic pair: one joint DPO step (two branches, fwd+bwd, gradient checkpointing) takes ~25 s and ~14 GB peak. At <= 9500 tokens expect ~40 s per pair, plus reference scoring (~12 s per branch) done once up front. The "each training run <= 3.5 h" cap is raised to 6 h for DPO (including reference scoring) and stays 3.5 h for SFT arms and the chosen-only control. If the projected time exceeds 6 h at the real pair count, stop and ping Sans instead of cutting updates.
4. **DPO implementation.** sft/r5_dpo.py (own implementation; the old Thesis-repo trainer is not reused). Joint two-branch autograd, vocabulary projection sliced to the continuation, fp32 log-softmax, sequence sums, adapter-only gradients asserted, pairs over the cap rejected. Preflight (on synthetic pairs, never used for training): policy == base at init, loss ln 2 at init, continuation masks and `<turn|>` end asserted, sliced-head logp equals full-logits logp, joint gradient equals sequential-branch gradient, descent step lowers the loss, longest-pair memory 14.2 GB.

## Amendments v2.3 (2026-11-08, after Codex r31; frozen before any pair sampling or E2 outcome)
1. **Eligible states (final).** 472 states / 180 tasks (153 recovery, 319 correction-only) after the K2-inclusive guard audit (dropped source tasks: distill_s2a_0016, distill_s2a_0285, distill_g_0184, distill_r3_0604, distill_r3_1176).
2. **Matcher, as implemented.** Excluded outright: truncated (finish_reason != stop) / API error, unparsable, no reasoning. Then, uniformly (including a stop label): exact (canonical calls equal) -> execution error (replay yields a result for which `benchmark.iffc_state.is_error_result` is true) -> premature stop (empty response while the teacher acts and the labeller's turn-complete test says the turn is not complete) -> return-equivalent (same_effect; excluded) -> unresolved (excluded). Replay/checker exceptions are `replay_exception` (excluded, counted), never evidence. Verified inferior = execution error or premature stop. `act_when_done` is NOT a rejected class (removed from the earlier draft).
3. **Strict parse, frozen.** A response counts only if the whole content is a JSON list whose items are objects with a string `function_name` and optional dict `parameters` and no other keys (a stricter schema than the historical bare-list filter; on the 1,103 historical native responses the two agree). Fences or prose are unparsable.
4. **Sampling.** Greedy + 5 samples at T=0.7 on the bar GGUF (no adapter; `/props` model path and build d344123fe asserted; exactly one rendered think marker asserted), NO explicit max_tokens (the historical native sampler sent none), per-request timeout 1800 s, job deadline 14,400 s. Resumable: only successful responses count as done; a manifest binds resumed runs to the original configuration. Pairs are built only when all 6 samples exist for every state. Chosen requires reasoning <= 3,500 characters; rejected needs non-empty reasoning only.
5. **Final-row provenance for pairs.** Both branches of every train and validation pair are expanded to rows (`r5_pairs.py expand`) and checked with `sft/check_provenance.py` (now also scanning `reasoning_content`) against dev_all, confirm, F and K2 with explicit paths; any hit drops the whole source task and the pairing, split and counts are recomputed under the same rule.
6. **Pair floor exit code.** `r5_pairs.py pairs` exits non-zero when the post-split floor (>= 150 train pairs from >= 50 tasks) fails; that is the registered stop for stage B. No sampling outcome changes the filters, pairing, split or floor. Floor risk is real (Codex r31 estimate: 100-200 train pairs).
