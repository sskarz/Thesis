\begin{abstract}
Small language models (SLMs) with fewer than five billion parameters are attractive for on-device agentic systems, but their reliability at consecutive, stateful tool calling remains poorly characterized under realistic edge serving stacks. This paper evaluates quantized SLMs on the Berkeley Function Calling Leaderboard (BFCL) v4, treating multi-turn execution accuracy as the primary agentic metric and single-turn AST categories as supporting diagnostics. All own experiments use llama.cpp build 8111 with Metal on a MacBook Pro M4 Pro; no own NVIDIA RTX~4090 numbers are reported.

On single-turn BFCL v4 AST (excluding parallel categories invalidated by a serving-layer grammar bug), Qwen3.5-4B Q4\_K\_M achieves the highest weighted accuracy at 817/990 (82.53\%), followed by Qwen2.5-3B Q4\_K\_M at 753/990 (76.06\%), FunctionGemma-270M bf16 at 395/990 (39.90\%), and Llama-3.2-3B Q4\_K\_M at 365/990 (36.87\%). Schema-aware type coercion plus a system prompt raises Llama-3.2-3B multiple-category accuracy from 41.5\% to 92.0\%, showing that much of the apparent inter-family gap was formatting rather than tool selection.

On multi-turn, Gemma-4-E2B-it Q4\_K\_M scores 54/200 (27.0\%) under native function calling (NFC) and 61/200 (30.5\%) under Instruction-Followed Function Calling (IFFC; Appendix~B of~\cite{taheri2026iffc}) on \texttt{multi\_turn\_base}. A TagDispatch-style constrained-decoding approximation (\textbf{not} full XGrammar-2) scores 21/200 (10.5\%), a scored negative. \section{Introduction}
\label{sec:intro}

Agentic applications require a model to select tools, fill typed arguments, incorporate execution feedback, and decide when not to call any tool at all. Errors early in a multi-step trajectory cascade: a wrong function, a mistyped argument, or a hallucinated call when none is needed can leave the environment in an incorrect state that later turns cannot recover. Cloud-scale models are routinely evaluated for these behaviors, but edge and local-first deployments need models that fit in a few gigabytes of memory and deliver interactive latency on consumer silicon.

This work studies small language models under five billion parameters served with llama.cpp~\cite{llamacpp} on Apple Silicon. The central questions are empirical:

\begin{enumerate}
  \item How accurately do quantized SLMs perform single-turn tool selection and multi-turn consecutive tool calling on BFCL v4 when served with Metal?
  \item How much of measured failure is format and serving infrastructure versus genuine agentic reasoning?
  \item Do inference-time format channels---native \texttt{tool\_calls}, JSON-in-text IFFC, shell dialects, grammar-constrained decoding, guided-structured templates, harness-written STATE working memory, Best-of-N majority voting, IFFC stop-on-repeat, IFFC-OODA-card, and IFFC-PTC-A---move the primary multi-turn metric?
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{BFCL and Gorilla.}
The Berkeley Function Calling Leaderboard (BFCL) and the Gorilla line of work evaluate large language models as API callers with AST and execution checkers, including multi-turn stateful trajectories~\cite{patil2023gorilla,patil2024bfcl}. We adopt BFCL v4 as the primary benchmark and treat \texttt{multi\_turn\_base} execution accuracy as the headline metric for consecutive tool calling.

\paragraph{Instruction-Followed Function Calling (IFFC).}
Taheri et al.~\cite{taheri2026iffc} argue that small reasoning models can act as instruction followers for function calling when tool use is expressed as constrained natural-language or JSON instructions rather than native tool APIs. That paper reports large gains on BFCL~V3 Live and Non-Live \emph{single-turn} categories for some models, often under full Algorithm~1 decoupling of a QA LLM from a small reasoning model (SRM). We implement Appendix~B JSON-in-text on the \emph{same} model for the full multi-turn loop, without dual QA/SRM decoupling. Dual-model IFFC remains \todo{deferred}.

\paragraph{XGrammar-2 and structured decoding.}
XGrammar-2 introduces efficient dynamic structured generation for agentic LLMs, including TagDispatch for tag-triggered grammar switches~\cite{dong2026xgrammar2}. That paper reports, for example, lifting Llama-3.2-3B correct-call rates from 33\% to 78\% under its engine---figures we cite as prior work only, not as our measurements. Our CD ablation approximates TagDispatch with two stock llama-server requests and \textbf{does not claim to run full XGrammar-2}. Guided generation and GBNF-style grammars more broadly are studied by Willard and Louf~\cite{willard2023outlines}; format restrictions can also hurt quality~\cite{tam2024format}.

\paragraph{Guided-structured templates.}
He et al.~\cite{he2025gst} propose seven-step guided-structured templates that improve function calling and interpretability over free-form chain-of-thought on BFCL v2 for several model families. We measure their Detail template as a prompt-only overlay on NFC (GST$+$NFC) on \texttt{multi\_turn\_base}; the checker executes native \texttt{tool\_calls} only and ignores GST draft text. This is \textbf{not} GBNF and \textbf{not} IFFC.

\paragraph{Type coercion and specialist SLM tool callers.}
Error taxonomies for sub-7B tool callers frequently rank type mismatch among the dominant failure modes (e.g., APIGen~\cite{liu2024apigen}). Specialist on-device models such as FunctionGemma~\cite{google2025functiongemma}, Hammer (function masking)~\cite{ye2025hammer}, and xLAM~\cite{zhang2024xlam} show that fine-tuning and format design can make small models competitive on tool calling. We situate our type-coercion result as an inference-time mitigation that does not change weights. Run~19 measures the published xLAM-1b-fc-r Q4\_K\_M GGUF on \emph{this} NFC multi-turn harness (0.0\%); Run~20 measures the same GGUF on the format-fixed \texttt{--fc-mode xlam} channel (3.0\%). Those are format-channel contrasts on this harness, not a reproduction of the published overall BFCL figure (${\sim}78.94\%$).

\paragraph{Working memory and test-time compute.}
ACON~\cite{xu2025acon} compresses older turns with LLM summarization. Our STATE overlay is a harness-written key-value snapshot from \emph{executed} tool results, not an LLM summary. Snell et al.~\cite{snell2024testtime} frame test-time compute versus parameter scaling; our Best-of-N is majority vote on tool-call tuples (MV@$N$), not tree search and not a learned verifier.

\paragraph{Training-time methods.}
QLoRA~\cite{dettmers2023qlora} is the standard efficient-finetuning reference for quantized LLMs. ToolACE~\cite{liu2024toolace} and xLAM~\cite{zhang2024xlam} supply the IFFC JSON-in-text mix used here. We train LoRA adapters with MLX~\cite{mlx} on Apple Silicon (not QLoRA-on-CUDA). Runs~12--13 are scored negatives on BFCL \texttt{multi\_turn\_base}; Run~15 is a scored recovery at 15.0\% that remains below IFFC and NFC; Run~16 (IFFC$+$STATE on that same v4 GGUF) is a scored negative/null overlay at 13.0\%; Run~17 (SFT-v5) is a scored regression at 11.5\% versus Run~15; Run~18 (SFT-v6) is a scored miss at 13.0\% versus Run~15. Run~19 (xLAM-1b NFC) is a scored format-channel collapse at 0.0\% on this harness; Run~20 (\texttt{--fc-mode xlam}) is the format-fixed fair-channel score at 3.0\% --- still very low, not a published-BFCL reproduction. Run~27 (IFFC-stop-repeat ungated on base Gemma) is a scored miss at 27.0\% versus IFFC. Run~30 (IFFC-stop-repeat tighten MIN=6) is the first scored win versus IFFC at 32.5\% on BASE, still below STATE 34.0\% and BoN 36.5\%. Run~42 (IFFC-OODA-card) is a scored Acc win versus Run~30 at 35.5\%, still below BoN, with a \texttt{state\_mismatch} gate \textbf{MISS}. Run~46 (IFFC-PTC-A) is a scored FAIL at 13.5\% versus Run~42/30/IFFC --- \textbf{bank and close}. We do not invent QLoRA scores.

\subsection{Benchmark and primary metric}
\label{sec:method-bench}

We evaluate on BFCL v4~\cite{patil2024bfcl}. Single-turn categories use the AST checker over simple (400), multiple (200), parallel (200), parallel\_multiple (200), irrelevance (240), Java (100), and JavaScript (50) cases. Multi-turn categories use the execution checker: the model enters an agent loop, tools execute against a live backend, and resulting state is compared to a reference trajectory. Categories are \texttt{multi\_turn\_base}, \texttt{multi\_turn\_miss\_func}, \texttt{multi\_turn\_miss\_param}, and \texttt{multi\_turn\_long\_context} (200 each). The primary optimization target is \texttt{multi\_turn\_base}. Secondary slices stress withheld tools, missing parameters, and long contexts.

\subsection{Format channels: NFC, IFFC, and shell}
\label{sec:method-channels}

\paragraph{Native Function Calling (NFC).}
The harness sends OpenAI-compatible \texttt{tools} and \texttt{tool\_choice} (typically \texttt{auto}). llama-server with \texttt{--jinja} may apply lazy tools GBNF after chat-template trigger tokens. Assistant outputs are native \texttt{tool\_calls}. This is the multi-turn baseline (Gemma-4-E2B-it Run~4). Run~19 applies the same NFC channel to published xLAM-1b-fc-r Q4\_K\_M (external baseline; format-channel collapse).

\paragraph{Instruction-Followed Function Calling (IFFC).}
Following Appendix~B of~\cite{taheri2026iffc}, we omit \texttt{tools} and \texttt{tool\_choice}. The system prompt instructs the model to emit a JSON list of objects with \texttt{function\_name} and \texttt{parameters} in assistant text. Tool results are fed back as user-role messages. Trajectories are mapped to BFCL function strings for the same \texttt{multi\_turn\_checker} used by NFC. This is Run~5 on \texttt{multi\_turn\_base} only. We do \textbf{not} implement dual-model QA/SRM decoupling in this draft.

\paragraph{Shell dialect (BFCL-FS ablation).}
An allowlisted Unix-like text dialect is mapped onto GorillaFileSystem function strings (e.g., \texttt{cd notes} $\to$ \texttt{cd(folder='notes')}) and scored with the existing multi-turn execution path. Evaluation is restricted to the fs-only subset where \texttt{involved\_classes} equals \texttt{["GorillaFileSystem"]}, $n{=}13$ on \texttt{multi\_turn\_base}. This is a format ablation, not a substitute for the full 200-entry score. Two harness versions (v1 and v2) were measured; both underperform NFC on the same IDs.

\subsection{TagDispatch-style constrained decoding (\texttt{--fc-mode cd})}
\label{sec:method-cd}

Full XGrammar-2 TagDispatch switches sub-grammars inside a single decode when structural tags are emitted~\cite{dong2026xgrammar2}. Stock llama-server does not expose that intra-request primitive (optional LLGuidance is off on the Mac Metal build used here). We therefore approximate TagDispatch with a two-pass protocol that never sends \texttt{tools} or \texttt{tool\_choice}, so native tools GBNF does not activate:

\paragraph{Pass 1 (dispatch).}
A GBNF grammar constrains the completion to either an empty list or a list of objects carrying only \texttt{function\_name} values drawn from an enum of the live tool list.

\paragraph{Pass 2 (dispatched arguments).}
For the selected name(s), a \texttt{json\_schema} (compiled by llama-server to GBNF) constrains an IFFC-shaped list of \texttt{\{function\_name, parameters\}} objects for those tools only.

The persistent multi-turn transcript remains IFFC-shaped; only completion requests carry grammar or \texttt{json\_schema}. \textbf{This is not full XGrammar-2} (no Cross-Grammar Cache, no intra-request tag switch, two HTTP requests when a tool is invoked). Run~8 scored this path at 21/200 ${=} 10.5\%$.

\subsection{Type coercion and system prompt}
\label{sec:method-coerce}

For Llama-3.2-3B, diagnostic inspection of multiple failures showed correct function selection with string-serialized integers, floats, arrays, and objects. We apply (i)~a system prompt requiring native JSON types and (ii)~schema-aware post-hoc coercion of argument values to the BFCL parameter types. Both are inference-time only (\texttt{benchmark/coerce\_types.py}).

\subsection{Parallel grammar bug and bypass}
\label{sec:method-parallel}

When \texttt{tools} are present, llama-server may compile a tools grammar whose repetition structure mismatches the model's trained multi-call delimiters (e.g., expecting comma-separated calls inside one block while the template uses separate \texttt{tool\_call} blocks). Generation can stop after the first closing tag, yielding truncated parallel output. For \texttt{parallel} and \texttt{parallel\_multiple} we implemented a bypass (\texttt{tool\_choice none} with content parsing of \texttt{tool\_call} blocks). Re-measurement after the fix is \todo{pending}; tables still report 0\% for those categories.

\subsection{Guided-structured templates (GST$+$NFC)}
\label{sec:method-gst}

Following He et al.~\cite{he2025gst}, we overlay the Detail guided-structured template as a one-shot system curriculum (\texttt{benchmark/gst.py}) on top of NFC: \texttt{tools} and \texttt{tool\_choice=auto} remain enabled. The model is instructed to write a \texttt{[GST]}\ldots\texttt{[/GST]} reasoning scaffold before native \texttt{tool\_calls}. The BFCL multi-turn checker executes \texttt{tool\_calls} only; GST draft text is ignored. \textbf{This is prompt-only---not GBNF, not XGrammar-2, and not IFFC.} Run~9 measures GST$+$NFC on Gemma-4-E2B-it \texttt{multi\_turn\_base}.

\subsection{IFFC $+$ harness STATE (\texttt{--fc-mode iffc-state})}
\label{sec:method-state}

IFFC$+$STATE keeps the Appendix~B JSON-in-text channel (no \texttt{tools} / \texttt{tool\_choice}) and adds a harness-written working-memory block. After each tool execution, the harness builds a compact \texttt{[STATE]}\ldots\texttt{[/STATE]} snapshot from real execution results and attaches it in user messages. The last two user/assistant$+$tool turns stay verbatim; older raw Function execution results dumps are dropped in favor of the accumulated STATE. \textbf{This is not GST, not CD/GBNF, and not LLM summarization.} Scoring still maps IFFC JSON to BFCL function strings. Run~10 measures this path on \textbf{base} Gemma (34.0\%). Run~16 measures the same overlay on the SFT-v4 GGUF (13.0\%, null/negative versus Run~15).

\subsection{Best-of-N on IFFC$+$STATE (\texttt{--fc-mode iffc-state-bon})}
\label{sec:method-bon}

Best-of-N rides on the IFFC$+$STATE channel so the 34.0\% baseline is not given back. At each agent step the harness samples $N$ completions at temperature 0.7 (default $N{=}5$), majority-votes the \texttt{(function\_name, arguments)} ballot, executes the winner once, then continues the IFFC$+$STATE loop. \textbf{This is majority-vote test-time compute~\cite{snell2024testtime}, not a verifier/reward-model Best-of-N, and not NFC/GST/CD.} Latency is approximately $N$ times a greedy IFFC$+$STATE decode. Run~11 measures $N{=}5$.

\subsection{MLX SFT-IFFC (LoRA best@1000, filtered v2, v4, v4$+$STATE, v5, and v6)}
\label{sec:method-sft}

We train LoRA adapters on Gemma-4-E2B-it with mlx-lm~\cite{mlx} using an IFFC JSON-in-text mix (ToolACE multi-turn~\cite{liu2024toolace} $+$ stratified xLAM~\cite{zhang2024xlam}), fuse a best-validation checkpoint, quantize to Q4\_K\_M, and evaluate under \texttt{--fc-mode iffc} on \texttt{multi\_turn\_base}. Run~12 uses best@1000 on the original mix (\texttt{gemma4-e2b-sft-iffc}). Run~13 uses best@2000 on a filtered mix that dropped 334 mid-trajectory empty-after-exec rows while keeping 552 terminal empty-after-exec rows (\texttt{gemma4-e2b-sft-iffc-v2}). Both mixes still teach stop-after-tools relative to BFCL multi-turn continuation needs.

Run~14 is a serve-time diagnostic on the v2 GGUF: \texttt{--iffc-strip-empty-assistant} removes trailing assistant \texttt{[]} from chat history before the next completion (\textbf{history bookkeeping, not a retrain, not a method win}).

Run~15 uses the v4 unroll on a new GGUF (\texttt{gemma4-e2b-sft-iffc-v4}, LoRA best@1600, val 0.196): keep the v3 empty-after-exec drop including terminal plus recovery rows, and additionally drop first-assistant-empty and clarifying empty-after-user \texttt{[]} targets. This is a training-mix change, not an inference overlay. The scored result is a recovery from collapse that remains below IFFC and NFC.

Run~16 applies \texttt{--fc-mode iffc-state} to that \textbf{same} v4 GGUF (no retrain). The scored result is a negative/null overlay versus Run~15 plain IFFC. We do \textbf{not} treat Best-of-N on this checkpoint as the next win.

Run~17 uses the v5 unroll on a new GGUF (\texttt{gemma4-e2b-sft-iffc-v5}, LoRA best@1800, val 0.147; ${\sim}29850$ train rows after prepare): keep every v4 empty-target drop and the recovery-after-\texttt{[]} curriculum, then drop underspecified turn-0, synthesize complete first-episode gold, and drop state-inconsistent continue-after-exec. This is a training-mix change, not an inference overlay. The scored result is a \textbf{regression} versus Run~15. We do \textbf{not} BoN this checkpoint and do \textbf{not} train more epochs on the v5 mix. v4 IFFC 15.0\% remains the best SFT recovery.

Run~18 uses the v6 unroll on a new GGUF (\texttt{gemma4-e2b-sft-iffc-v6}, LoRA best@1800, val 0.142): v4 empty/recovery plus only \texttt{drop\_state\_inconsistent}; turn-0 underspec drop and synthetic complete turn-0 off. The scored result is a \textbf{miss} versus Run~15. We do \textbf{not} BoN this checkpoint and do \textbf{not} train more epochs on the v6 mix.

\subsection{xLAM-1b NFC external baseline (\texttt{--model xlam-1b --fc-mode nfc})}
\label{sec:method-xlam}

Run~19 serves the published Salesforce xLAM-1b-fc-r Q4\_K\_M GGUF (\texttt{Salesforce/xLAM-1b-fc-r-gguf}; registry key \texttt{xlam-1b}) on the \textbf{same} stock NFC harness as Gemma Run~4 (native \texttt{tools}/\texttt{tool\_calls}; no new parser, no IFFC, no STATE, no BoN). \textbf{This is not a new method.} The measured 0/200 is a format-channel collapse on this harness: NFC never parses assistant \texttt{content}. A negative NFC external baseline versus Gemma NFC 27.0\%, \textbf{not} a claim that xLAM scores 0 on BFCL overall, and \textbf{not} the published overall figure of ${\sim}78.94\%$.

\subsection{xLAM JSON-in-text fair channel (\texttt{--model xlam-1b --fc-mode xlam})}
\label{sec:method-xlam-xlam}

Run~20 serves that \textbf{same} published GGUF with \texttt{--fc-mode xlam} (PR~\#42): no native \texttt{tools}/\texttt{tool\_choice}; Salesforce-style JSON-in-text system prompt; parse \texttt{\{"tool\_calls":[\ldots]\}} from assistant \texttt{content}. \textbf{This is a format adapter, not a new training method.} The measured 6/200 ${=} 3.0\%$ is the format-fixed fair-channel external baseline after Run~19. Smoke extracted calls; the full score is still \textbf{very low} --- tools actually execute (mean \texttt{api\_calls} 50.47 versus Run~19 3.63), but over-calling, parse fails, and state drift dominate. \textbf{Not} a method win. \textbf{Not} published overall BFCL ${\sim}78.94\%$. Still below CD 10.5\% and all Gemma/SFT/BoN numbers.

\subsection{Hardware and serving stack}

This draft does \textbf{not} claim RTX~4090 results for own measurements. \todo{NVIDIA Jetson Orin Nano Super (CUDA, 8~GB) replication.}

\subsection{Models}

Single-turn matrix (Q4\_K\_M unless noted): Qwen2.5-3B-Instruct, Llama-3.2-3B-Instruct, Qwen3.5-4B, and FunctionGemma-270M-IT (bf16; only published precision). \subsection{Evaluation protocol}

Single-turn: BFCL AST checker. Multi-turn: BFCL execution / \texttt{multi\_turn\_checker}. FunctionGemma nonstandard control-token outputs are normalized via a dedicated parser when llama-server does not already map them to \texttt{tool\_calls}. Weighted single-turn averages exclude \texttt{parallel} and \texttt{parallel\_multiple} because those scores are invalidated pending re-run (990 cases: simple, multiple, irrelevance, Java, JavaScript). Failure buckets in Section~\ref{sec:results} use one primary error per failed \texttt{entry\_id} unless noted as eval-error \emph{row} counts.

\section{Discussion and Limitations}
\label{sec:discussion}

\paragraph{Format channel helps modestly; residual is state tracking.}
IFFC improves \texttt{multi\_turn\_base} by ${+}3.5$ percentage points and sharply cuts empty-turn and state-mismatch error rows, but 124 of 200 entries still fail under both NFC and IFFC. Once the model can emit valid calls, consecutive correctness is limited by environment-state fidelity across turns, not by whether the channel is native tools or JSON-in-text.

\paragraph{Paper-scale IFFC gains do not transfer to \texttt{multi\_turn\_base} without dual QA/SRM.}
Large lifts in~\cite{taheri2026iffc} are reported on single-turn Live/Non-Live suites, often where NFC is already weak, and under full Algorithm~1 decoupling. Our Appendix~B-only multi-turn setup sits in the modest-gain band. Dual-model IFFC remains \todo{open}.

\paragraph{Constrained decoding (TagDispatch-style) is a scored negative on this stack.}
Run~8 at 10.5\% underperforms NFC and IFFC. The two-pass name-then-args approximation on stock llama-server appears to trade semantic flexibility for syntactic validity in ways that hurt multi-turn execution accuracy. \textbf{This is not a claim about full XGrammar-2 TagDispatch.}

\paragraph{GST$+$NFC ties IFFC but does not beat it.}
Run~9 matches IFFC's 61/200 via different entries. Empty turns drop versus NFC while state mismatches rise---consistent with a scaffold that promotes calling without improving env-state tracking when drafts are checker-ignored. Simply porting He Detail onto NFC is the wrong lever for beating IFFC on \texttt{multi\_turn\_base}. \textbf{GST is not GBNF and not IFFC.}

\paragraph{IFFC$+$STATE breaks the 30.5\% plateau on base Gemma.}
Run~10 at 34.0\% nets ${+}7$ versus both IFFC and GST via a rescue/regress swap, not pure dominance. Empty turns improve; \texttt{state\_mismatch} does not. Remaining headroom is VehicleControl/GorillaFileSystem fidelity and under-call recovery (64 ${+} 37$ failed entries). \textbf{STATE is not LLM summarization.}

\paragraph{Best-of-N buys another ${+}2.5$\pp\ at ${\sim}7\times$ generate cost on base Gemma.}

\section{Conclusion}
\label{sec:conclusion}

Quantized SLMs on a MacBook Pro M4~Pro with llama.cpp Metal already achieve strong single-turn tool selection for Qwen-family 3--4B models (weighted non-parallel AST up to 82.53\%), while specialist FunctionGemma delivers interactive latency at 270M parameters. Inference-time type coercion largely closes Llama's multiple gap (41.5\% to 92.0\%). For consecutive tool calling, Gemma-4-E2B-it reaches 27.0\% NFC and 30.5\% IFFC on \texttt{multi\_turn\_base}; TagDispatch-style CD scores 10.5\% (scored negative; \textbf{not} full XGrammar-2); GST$+$NFC ties IFFC at 30.5\% without beating it (\textbf{not} GBNF); IFFC$+$STATE reaches 34.0\% on \textbf{base} Gemma (\textbf{not} LLM summarization); Best-of-N $N{=}5$ on that channel reaches 36.5\% (MV@$N$, \textbf{not} verifier BoN) at roughly $7\times$ generate wall clock. Both MLX SFT-IFFC LoRA checkpoints (v1 and filtered v2) collapse to 0.5\% via stop-after-tools; stripping \texttt{[]} from history on v2 only reaches 2.0\% and is a diagnostic, not a method win. SFT-v4 recovers to 15.0\% by dropping first-assistant-empty and clarifying \texttt{[]} targets, still below IFFC 30.5\% and NFC 27.0\%; empty turns are largely fixed and residual error is state tracking. IFFC$+$STATE on that same v4 GGUF scores 13.0\% (null/negative versus 15.0\%); STATE helps base Gemma, not this checkpoint. SFT-v5 scores 11.5\% (scored regression versus v4 15.0\%); empty is fully suppressed (0) while state mismatch rises. SFT-v6 scores 13.0\% (scored miss versus v4 15.0\%); empty stays rare (1) and \texttt{api\_calls} return to a sane range (13.34 versus v5's 40.3), but state mismatch (118) and under-call (55) remain. xLAM-1b NFC scores 0.0\% on this harness (Run~19): a format-channel collapse versus Gemma NFC 27.0\%. The format-fixed \texttt{--fc-mode xlam} channel scores 3.0\% (Run~20): tools actually ran, but the score is still very low and \textbf{not} a method win. Neither figure is published overall BFCL ${\sim}78.94\%$. IFFC-stop-repeat ungated on base Gemma scores 27.0\% (Run~27): a scored miss versus IFFC 30.5\% (PR~\#54 commit \texttt{5b49d7a}; \textbf{not} a method win; \textbf{not} smoke81 / v7 / v8). IFFC-stop-repeat tighten MIN=6 scores 32.5\% (Run~30): the \textbf{first scored win versus IFFC} on BASE (PR~\#54 commit \texttt{78c22a0}; still below STATE 34.0\% / BoN 36.5\%; \textbf{not} best overall inference). IFFC-OODA-card scores 35.5\% (Run~42): a dedicated one-pass \texttt{[OODA]} card (PR~\#61; ${+}3.0$\pp versus Run~30; still below BoN 36.5\%; \texttt{state\_mismatch} 71 gate \textbf{MISS}; \textbf{not} a clean gate sweep). IFFC-PTC-A scores 13.5\% (Run~46): a dedicated live tool-name DFA (PR~\#63; ${-}22.0$\pp versus Run~42; \texttt{state\_mismatch} 102 gate \textbf{MISS}; \textbf{scored FAIL; bank and close}; PTC-B \textbf{HOLD}). Format and scaffold changes help modestly, but state tracking dominates residual error on Gemma, while xLAM's NFC miss is a channel-compatibility result and the fair-channel 3.0\% is an over-calling / state-drift miss. Completing parallel re-runs, multi-model multi-turn baselines, Jetson replication, and dual-model IFFC will determine how far inference-time and light training methods can push edge agent reliability before December 2026. The next SFT mix lever after the v6 miss versus v4 is \todo{TBD}; do \textbf{not} BoN the v6 checkpoint or train more epochs on that mix; SFT v9.2 10-ID smoke-gate FAILed (Run~36 avg api 25.7, hit 6/10) --- park; do \textbf{not} invent a v9 BFCL \%. Next path after Run~46 FAIL $=$ DPO pair-audit (PR~\#57 stays draft), \textbf{not} more PTC/OODA remix.
